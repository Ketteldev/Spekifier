# Phase 6 selection evidence and acceptance

Automated validation uses production selection, window, columns, resolver, auto-show and event code in Lua 5.1. Run `lua Tests/LootSpecialization.lua`. It runs the 267-check lifecycle fixture and adds 95 focused checks. All existing suites also pass: 79 provider, 44 window integration, 117 presentation and 166 shared-loot checks. There are 768 unique checks across the suites; repeated lifecycle runs are not counted again.

## Live procedure (record results before checking live boxes)

1. Enable Lua errors (`/console scriptErrors 1`), reload the addon, and target a supported living raid boss outside combat. Record client build, class, active spec, encounter and difficulty. Check the initial Selected marker against the player portrait Loot Specialization menu. Repeat opening with an explicit choice and with Current Specialization.
2. Click every spec header in turn, then select using an item row and an empty column background. After each click, verify the window closes and chat prints exactly `Spekifier has set your loot specialization to [SPEC].` once in system colors. Open Blizzard's loot-spec menu to verify the specific specialization. Wait for target/zone refresh events: the preview must remain dismissed. Manually reopen before the next click and verify the confirmed Selected marker. Test with loading/empty loot too; selection depends on a supported context, not a finished loot request.
3. Hover every header, row, column background and shared icon without clicking. Check that tooltips/highlights still work and the game choice never changes. Right-click a header/row: it must not set loot spec.
4. While the window is open, select a different explicit loot spec through Blizzard's menu. The marker should move without a new popup or confirmation for an addon click. Select Current Specialization and change active spec outside combat; the effective marker must follow. Repeat active changes with an explicit loot spec: that loot marker must stay fixed.
5. Dismiss the preview, change loot spec in Blizzard's menu and wait for events. It must stay dismissed. Manually reopen: the latest game choice must be marked. Disable automatic opening and repeat manual selection in a valid context. Reload: the marker must come from game state, not saved addon state.
6. Test raid target clearing, death, unsupported target, another supported encounter and difficulty change around clicking. Obsolete columns must not select. Enter combat: the window must close, cannot reopen, and selection must produce no protected/blocked-action errors. Retest the normal lifecycle after combat.
7. Enter a supported ordinary Mythic dungeon with no target or started key. Click each specialization and verify it in Blizzard's menu. Repeat in an active Mythic+ instance. Clear/change targets; selection should remain available outside combat. Exit or enter a different dungeon around clicking; the previous visit's data must not select. Normal/Heroic and unsupported manual previews must keep selection unavailable.
8. During any observed selection failure, record feedback, prior game setting, marker and eventual game update. A pending selection should not move the marker before confirmation; after about two seconds an unconfirmed attempt should explain the failure. Close or change contexts while waiting: no old notice should reappear. Record all Lua/taint errors, if any. Repeat relevant checks on a class with a different spec count.

## Primary API evidence

- [Blizzard exported PlayerScript documentation](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/PlayerScriptDocumentation.lua): setter accepts specialization ID, getter returns specialization ID, setter has no success return and arguments have taint restrictions.
- [Blizzard exported Loot documentation](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/LootDocumentation.lua): loot-spec update event has no payload and may be synchronous.
- [Blizzard exported specialization documentation](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/SpecializationInfoDocumentation.lua): specialization indices and IDs are distinct; talent update is an appropriate retry event.

These exports verify API shape, not actual in-game execution or visual/input acceptance. Live results remain pending.
